一个**原生 Windows 置顶悬浮球**，报告 DeepSeek Harness 里**所有会话**的整体状态：现在有几个
会话在跑、有没有东西在等你；模型提问或请求审批时高亮提醒，**可以直接在球上作答**（选选项、
也可以自己写一句）。展开之后的面板是**一条一条的会话条目**：一个会话一条，每条自带那个会话的
输入框与属于它的卡片 —— 想给谁说话就在谁那一条里打字，不用先挑"发给谁"。它浮在所有窗口之上，
不依赖于浏览器，也不依赖于前台窗口。

**为什么要它**：Harness 的 Web UI 是浏览器里的一个页面。模型一开始操作桌面（`desktop_step`
会真的去动你的鼠标键盘），页面就失去前台位置，提问、审批全都被挡在后面 —— 你不知道它在想
什么、是不是卡住了、有没有在等你回答。页面里的任何元素都做不到"浮在别的窗口之上"，所以这个
球是**另一个进程里的原生窗口**（Windows PowerShell + WPF），由插件从 Host 侧喂数据。

**球上只显示"状态"，不显示"内容"**：思维链、正文、以及工具调用的参数与结果都不显示。面板留下
的就是：整体状态行、一条一条的会话条目（每条自带它自己的输入框与卡片）、以及页脚那行提示。
球的**颜色**是整体口径 —— 某个会话在思考、在写、在调工具都不会让它按**步骤**变色，所以几个
会话同时跑时它不会来回跳；它说的是三件事：**有会话还在输出**（蓝）、**有人在等你**（琥珀/红）、
**有会话出错**（红）。面板上的**条目**则是按会话分的，每个会话一条，各自写着自己是谁。

```
┌─ 收起 ─┐        ┌──────────── 展开 ─────────────────────────┐
│   ●DS   │  单击   │ ● 1 个会话在跑              [＋ 新会话] [-] │
│  (带徽标) │ ─────▶ │ 输出 12.3k tokens · 子代理 1 个在跑        │
└────────┘        │ ┌ ● 修复颜色表现         [知道了] [×] ────┐ │
  拖动可移动        │ │ 出错 · 3 分钟前 · C:\work · #6250      │ │
                  │ │ 本轮出错：工具调用超时                 │ │
                  │ │ [在这里输入，回车发给模型…]      [发送] │ │
                  │ └───────────────────────────────────────┘ │
                  │ ┌ ● 整理素材                     [×] ────┐ │
                  │ │ 运行中 · 刚刚 · C:\work · #a145        │ │
                  │ │ [会话正在输出，跑完这一步再发]  [输出中]│ │
                  │ └───────────────────────────────────────┘ │
                  │ 拖动面板可移动 · 点右上角「-」收起          │
                  └───────────────────────────────────────────┘
```

## 外观与几何

- **收起的小球是三个同心圆**：底色球体（`ballSize`）、状态色圆环（空闲时灰、**还有会话在输出时
  蓝**、在等你/出错时琥珀或红）、以及**只要有会话在跑就亮、而且是呼吸的**白色光晕。球的尺寸是
  `ballSize + 18`（光晕每边比球体大 7px，再留 2px 余量给窗口边）。
- **展开面板**：`panelWidth` 是最终宽度，`panelHeight` 是**上限**。一条条目都没有时，面板自己
  缩到表头 + 那行提示那么高；条目多起来就长到 `panelHeight` 为止，再多就在面板里自己滚动。
- 球的大小与窗口的整体不透明度是 `ballSize` 与 `opacity` 两个常量，不随模型在做什么而变；
  随状态变的只有**颜色**与那层光晕的呼吸（见下一节）。

## 状态与颜色

球的颜色是**整体口径**：它不跟着任何单个会话的步骤变，所以几个会话同时跑时不会来回跳。

| 状态 | 颜色 | 什么时候出现 | 状态字 |
|---|---|---|---|
| 空闲 | 灰 `#FF7C8598` | 没有待办、没有未确认的出错、**也没有会话在输出** | `空闲` |
| 还有会话在输出 | 蓝 `#FF5B8DEF` | 有会话在跑（思考 / 生成 / 调工具都算，见下） | `2 个会话在跑` |
| 正在向你提问 | 琥珀 `#FFE0A64B` | 有提问卡片在等你作答 | `正在向你提问` |
| 正在请求审批 | 红 `#FFE0574B` | 有审批卡片在等你批准 | `正在请求审批` |
| 出错了 | 红 `#FFE0574B` | 有会话出错、而且**还没被确认**过 | `出错了` |

- **优先级**：审批 > 提问 > 未确认的出错 > **还有会话在输出** > 空闲。前三种都是"要你看一眼"
  的事，不该被"有会话在忙"盖过去；反过来，蓝色那条**排在最后**是因为它自己会消失（见下一节），
  而红色那条**要人来清**（见「出错的红要人来清」）。
- **思考 / 生成 / 调工具不改变颜色**：那三件事只决定"这个会话算不算在跑"，而球说的是整体
  ——"还有没有人在跑"。所以同一支蓝色不会因为哪个会话换了步骤而闪。
- 徽标上的数字是当前可见的待办卡片数；光晕表示"有任何会话在跑"，而且它在跑的时候是**呼吸**的。
- 第二行是整体统计：`2 个会话在跑 · 输出 12.3k tokens · 子代理 1 个在跑`；出错时还会写明是
  哪个会话出错、为什么。**哪条条目是哪个会话不在这里写** —— 每个会话的条目上自己写着（见
  「展开后的面板：会话条目」）。

## 跑完了没有：球的颜色自己会回来

这一节说的是**球上那条"任务完结"的信号**，而它不需要任何额外的"完成"提示：状态自己会消失。

- **还在输出的时候，球是蓝的，而且环与那层白晕都在呼吸**（一明一暗，约 1.1 秒一次）；**最后一个
  会话停下来，蓝色回到空闲灰、呼吸停掉、光晕灭掉** —— 球安静下来就是这一轮结束了。余光里就能
  判断，不必点开面板、也不必读那一行字。
- **判据就是那个"几个会话在跑"**（与条目里那把输入框的锁同一份判断，见「在条目里给会话发话」）：
  会话目录说它在跑，**或者**球自己看到了它还在回合里（`turn/start` 之后、`turn/end` 之前），
  两条取并集，减去"正在等你作答的那个会话"（那一刻模型在等人，不是在跑）。子代理不进来
  （它照样计进统计行的"子代理 N 个在跑"）。
- **为什么蓝色排在待办与出错之后**：那三种状态是"要你动手/看一眼"的，颜色归它们。这时球不会
  因为"还有别人在跑"而变蓝，但**白晕照旧在呼吸** —— 所以"任务还在跑"这件事在任何颜色下都看得见。
- **只在蓝色下呼吸**：琥珀/红要稳稳地等你，不该闪。
- **它不跟着某个会话的步骤变**：几个会话同时跑时，蓝色只表示"还有人在跑"，不会因为谁换了步骤
  而跳。所有会话都停下来，它才回灰。
- **对着还没重启的旧宿主也能用**：状态文档里带着版本号，v7 之前的宿主根本没有"还在输出"这一
  颜色（它把这件事只写在状态字里）。球对那样的文档会**自己**把这一状态画成蓝的并让它呼吸，
  所以这一节说的东西不要求你先重启 Harness（v7 之后颜色由宿主给，那段兜底自动失效）。

## 出错的红要人来清（「知道了」或「×」）

出错会把球染红。这条红**不会到点自己消失**，走得掉的只有两条路：

1. 你在**那条出错条目**上按一下「知道了」，或者干脆把那条**「×」掉**（两者都算确认，见下）；
2. 那个会话**又开始了新的一轮**（它自己继续干活了）—— 这条错误就不再算了。

两条谁先到算谁。第 2 条是原本就有的行为，第 1 条的存在是因为很多会话出错之后就**一直闲在那里**：
一个被你按停、之后再也不用的会话，本来能让球红上很久，现在你随时可以点掉它。

- 按下「知道了」之后：球不再为这条错误染红（整体颜色按剩下的情况重新算，统计行里的"出错"也跟着
  干净），但**条目留着**、状态词写成「已确认出错」、那行出错原因还在。要把它从面板上拿掉请点「×」。
- **「×」也包含「知道了」的意思**：「知道了」按钮长在条目上，条目一被「×」收走，那条红就没有任何
  地方可以确认了（球会一直红到那个会话自己又跑起来为止）。所以收条目的同时会把它名下的出错一并
  确认掉：条目消失、红也消失，页脚写着「已从面板上收起这一条，并确认了它的出错」。换句话说，
  **清掉这条红永远有一个够得着的入口**：留着条目按「知道了」，或者连条目一起「×」掉。
- **面板条目达到上限时，带未确认出错的条目不会被挤掉** —— 与上一条是同一个道理（确认的入口长在
  那一条上）。
- **红色会回来**：那个会话**下一次开始输出**或者**又出了一次错**，红色照旧亮起来 —— 后一种情况
  会重新要一次确认。照原样重复的同一条错误（同一轮、同样的原因）不会反复提醒你，换了一轮、或者
  原因变了，就重新算一次。
- **「本轮被中止」也算出错**：你或模型把一轮停下（`aborted`）与真正的报错走同一条路，一样染红、
  一样靠「知道了」或「×」清掉。

## 展开后的面板：会话条目

面板由**会话条目**填充，从上到下依次是：表头（状态点、状态字、「＋ 新会话」、「-」收起）、
统计行、条目列表、页脚提示。**没有**底部的「发送到」下拉、也没有面板级的输入框 —— 目标和输入框
是同一个东西，就在那个会话自己的条目里。

- **一个会话一条**。条目**出现**在这些时候：那个会话正在输出、有提问/审批卡片在等你、或者刚
  出错（还没被确认）。条目一旦出现就**不会自己消失**：会话闲下来它只是变灰留着（状态词写成
  「空闲」），这样你还能随时给它补一句话。
- **要移除它，点条目右上角的「×」**（见下）。被「×」收掉之后，那个会话**下一次"有事"**就会让
  条目重新回来 —— 回来时是**重新长出来的那一条**，所以面板上不会留下两份（已有的条目也永远不会
  重复渲染）。算"有事"的只有这几种，**同一个回合里的每一步不算**（所以对着一个正在跑的会话点
  「×」是留得住的，不会下一步就被加回来）：
  - 那个会话**开始新的一轮**（你在网页端或球上发了话，或者它自己接着往下走）；
  - **人又说了一句**（`user/message` 且来源是用户 —— 这正是"我把它删了、后来又跟它说话"那条路）；
  - **会话目录说它开始跑了**（它常常比回合事件先到，所以这一条单独也算一次）；
  - 来了一张**提问/审批卡片**，或者**又出了一次错**。
- **每条条目里是这些东西**：左上角一个状态点 + 整条边框的颜色、会话名（标题）、第二行明细、
  属于这个会话的卡片（提问/审批，来了才画）、它自己的输入框与发送按钮、出错时多一行出错原因、
  以及右上角的「知道了」（只有未确认的出错才有）与「×」。
- **新条目插在最上面**（最新的一条在面板顶部），已有条目不会因为面板刷新而挪位置 —— 所以你在
  某一条里打字的时候，别的地方来了新动静也不会把你的框挪走或清空。
- 面板上一条条目都没有时，那里写着一行：`现在没有进行中的会话：点右上角「＋」新建一个。`

### 条目上的颜色与两行字

整条边框与状态点用的是同一个颜色，一眼就能看出这条现在算什么：

| 这条现在是什么 | 颜色 | 状态词 |
|---|---|---|
| 在等你回答（有提问卡片） | 琥珀 `#FFE0A64B` | `等你回答` |
| 在等你批准（有审批卡片） | 红 `#FFE0574B` | `等你批准` |
| 出错、还没确认 | 红 `#FFE0574B` | `出错` |
| 正在输出 | 蓝 `#FF5B8DEF` | `运行中` |
| 出错但已经确认过 | 灰 `#FF7C8598` | `已确认出错` |
| 这一条留着、但它已经闲下来了 | 灰 `#FF7C8598` | `空闲` |

- **第一行是会话名**，取法与网页端侧边栏同一套：**标题 → 首条人写的消息 → 目录名 → 新会话/
  未命名**。标题是异步落下来的，所以一个刚建的会话会先显示成「新会话」，等标题到了自己换过来。
- **第二行是明细**：状态词 · 多久以前 · 目录 · 会话号尾巴，例如
  `运行中 · 3 分钟前 · C:\work · #6250`。那串尾巴（`#6250`）是"这一条到底是哪个会话"的硬证据
  —— 会话名太长会被裁成省略号、同名会话也可能撞在一起，而尾巴不会（`ball.log` 里的发送回执
  用的也是同一串尾巴）。
- 同一个条目上有几件事同时成立时，按这个优先级挑一个来说它现在算什么：审批 > 提问 >
  未确认的出错 > 正在输出 > 已确认的出错 > 空闲。

### 「×」：把这一条从面板上收掉

- 收掉的只是**这一条**，那个会话本身一点不受影响：它照样在跑、照样在网页端等你作答。页脚会
  明说这一点。
- **「×」同时就是「知道了」**：那一条如果正带着一条还没确认的出错，收走它的同时会把它一并确认
  （条目消失、球上的红也消失，页脚写「已从面板上收起这一条，并确认了它的出错」）。少了这一下，
  红就没人能清了 —— 「知道了」按钮长在条目上。
- 那一条上如果正挂着提问/审批卡片，**卡片也跟着看不见了** —— 网页端那个弹窗照旧在，哪边先答
  都算数。所以「×」不是"拒答"，它只是把球上这一条收走。
- 想让这条回来，等那个会话**再有新动静**（见上一节的四种）就会自己回来。
- 面板上的条目有上限（`entryLimit`，默认 12 条）：超了先挤掉最旧的、**此刻没事**的那些。三种永远
  不挤：**正在输出**、**手上有卡片**、以及**带着还没确认的出错** —— 最后那一种跟「×」要顺手确认
  是同一个道理（确认的入口长在那一条上，挤掉它红就点不掉了）。被挤掉的与「×」收掉是同一件事 ——
  那个会话下一次有事照样回来。

### 「＋ 新会话」

表头右上角那个「＋ 新会话」按钮是球上**新建会话**的入口（`sessionController.create`）：

- 点开是一个**一行 = 一个工作区**的列表（明细行写着那个目录）。选一个，面板上就多一条**空条目**：
  标题写着 `新会话 · 工作区名`，明细写着目录，输入框直接可用。
- 在这条里打的第一句话发出去时，会**在那个工作区里新建一个会话**，再把这句话发进去。带上
  `workspaceId` 是刻意的：只有这条路会把新会话登记进那个侧边栏分组，只给目录的话它会一直挂在
  「未分组」里。
- 回执回来（带着真会话 id）时，这条本地条目就**交接**给真会话那条：本地那条消失，真会话的条目
  出现，提示行写着 `已新建会话（work），并把这句话发了出去。`。这句话到底落在哪个工作区，是这次
  新建最该被确认的一件事。
- 这条本地条目上的「×」只是把它自己拿掉，**不通知宿主** —— 宿主根本不知道它存在过（一句话都
  没发出去，也就没有会话要收拾）。它也没有"出错"可确认，所以不涉及那条红。
- **注册表里一个工作区都没有时，按钮照样能用**：那时列表里是唯一一条兜底行，明细写着它会落在
  哪儿 —— **最近在用的那个目录**（你刚说过话的那个会话的目录；一个会话都没见过就交给 Harness 的
  默认目录，那时明细写着「Harness 默认目录」）。这一条走的是 `cwd`，**不会**登记进侧边栏的工作区
  分组，所以那一类新会话可能出现在「未分组」里。总比按钮是灰的、根本建不出来好。
- 有几个工作区就都给你列出来，由你当场挑；一个都没有时才出现上面那条兜底行。

## 在条目里给会话发话（每条自己的锁）

每条能说话的条目底下都有一行：**输入框 + 发送按钮**，目标就是这一条的那个会话。所以不存在
"发给谁发错了"这回事（早先那套"在面板底部选一个「发送到」再打字"的做法没有了）。

发出去的话会变成**那个会话的一条普通用户消息**，与你在网页端输入框里发的一模一样（来源、去重、
排队/插话、模型与附件校验全都同一套），因为它走的就是网页端那个入口
`ctx.sessionController.prompt`（优先走 `ctx.typertGateway.invoke()`，失败才退回直连；一次发送
只用一个 `requestId`，服务端按它去重）。成败都写进球的 `ball.log`，失败那条还带完整栈。

发送之后**面板留在原地**：那个框清空、面板不收起。成败写在两个地方：**那一条自己的提示行**上
（就在刚打字的框下面，15 秒）与页脚那一行（宿主 `setNotice()`，同样 15 秒）。

**那个会话正在输出的时候，它这条的输入框与发送按钮是禁用的**。点发送的那一刻它们就变灰了
（球发出动作的同时自己就锁上，不等宿主回话），然后：

| 什么时候 | 输入框 | 发送按钮 | 输入框上的水印 |
|---|---|---|---|
| 空闲（这个会话没在跑） | 可用 | 可点，写着「发送」 | 「在这里输入，回车发给模型；Esc 交还键盘」 |
| 刚点完发送、还没等到会话接手 | **灰** | **灰**，写着「输出中」 | 「已发出，等会话接手…」 |
| 这个会话正在输出 | **灰** | **灰**，写着「输出中」 | 「会话正在输出，跑完这一步再发」 |
| 这一轮跑完 | 自己恢复可用 | 恢复「发送」 | 回到常态那句 |

- **锁只影响那一条**：别的条目的框一点不受影响 —— 甲在跑的时候你照样能跟乙说话。
- **"正在输出"由宿主按条目算好给你**（状态文档里每条条目自己的 `lock`）：判据是两条取并集
  —— 会话目录说它在跑（`api-session/status`），**或者**球自己看到的那个会话还在回合里（内部
  步骤状态，不是球上的颜色）。**正在等你作答的会话不在其中** —— 那一刻模型在等人，这个框正是
  这时候最该能用。
- **锁住期间不能再插话**（`steer` 那一路恰恰只在模型跑的时候有意义）。想要保留插话就把
  `lockComposeWhileBusy` 关掉：那时宿主不把任何条目算成"锁"，所有框一直可用；只有**刚点完发送的
  那一两秒**还会锁一下（球自己那道短锁：发出动作的瞬间就锁，不等宿主回话，收到回执后缩到
  1.5 秒）。
- **锁住时键盘立刻交还**：禁用的框收不了按键，球不会端着前台守着一个打不了字的框。这一轮跑完
  之后想接着说，点一下那个框就行。
- 发送**失败**立刻解锁，并把原因写在那一条自己的提示行上，让你能就着刚才那句重发。
- 回车发送、`Esc` 交还键盘；框里的内容可以正常选中、复制、粘贴（球上的其他文字不行，见「已知
  边界」）。

## 提问 / 审批卡片

卡片渲染在**它所属会话的那条条目里面**：谁在问、谁在等批准，看它挂在哪一条上就够了。

- **卡片上有这些**：标题（"模型在等你回答 / 在等你批准"）、**选项按钮**、**"自己写一句"的
  输入框**（提问），以及最下面那个「在球上作答」（审批卡片则是「允许一次」/「拒绝」）。卡片上
  **不再有「来自：…」那一行** —— 它已经在那个会话自己的条目里了。
- **选项按钮的选中状态只有一个规则**：点一下就选中（填色 + `●`），再点一下取消（`○`）。
  单选问题点另一个选项就是换过去，被换掉的那个随即回到未选中 —— 视觉永远是从"实际选了什么"
  重画出来的。
- **答不全就明说**：还有哪道题没选、也没写，点「在球上作答」不会静默失败 —— 那道题下面会
  出现"每个问题都要选一项或填一句，再点「在球上作答」"。
- **卡片里的输入框和条目里的输入框一样能打字**：它同样走那套"临时拿键盘"的机制。
- **卡片上没有「先收起来」按钮了**：要把卡片从球上收起来就点那条条目的「×」（见「×：把这一条
  从面板上收掉」）。网页端那张照旧，请求本身也照旧活着；超时后仍可作答的提问，答案会作为一条
  补充消息交给模型。
- 卡片多的时候（同一条里有好几张，或好几条各自挂着卡），面板自己滚动。

两个监听器都**第一瞬间就 `next()`**，所以网页端的卡片/弹窗照常弹出、一点都不变慢；球上同时
出现同一份内容，**哪边先作答就以哪边为准**。球被忽略时，一切行为与没有这个插件时完全一致。

- **提问**：带 `timeout` 的提问在前台等待结束后会变成 `continued` 状态，这时球上的作答走
  `ctx.userQuestions.answer(...)`，把答案作为一条用户消息送进会话 —— 所以"人不在电脑前、回来
  才看到球上的问题"也不会白问。球上的卡片会明确显示当前是哪种状态（带一行倒计时）。
- **审批**：没有等价的带外接口，所以球上的批准/拒绝是通过同一个 waterfall 落地的，会**抢在
  网页端之前**生效（`allowed-once` / `rejected`）。**审批有真实副作用**，介意就把
  `answerApprovals` 关掉 —— 那时球只显示、不作答。
- **球上先答会把网页端那张卡收掉**：请求既然是在 waterfall 里被球抢答的，前台那条投递会一直
  悬着，所以作答成功后会**撤销这条请求的投递**，网页端那张卡片随即自己收起。
- **网页端先答，球上这张卡片也会下来**：审批卡片靠 `approval/asked` 与 `approval/decided`
  这一对凭据收场（**按 `callId` 配对**，配不上号时什么都不做，宁可留着也不误收），提问卡片靠
  工具结果 + `userQuestions` 投影对账。真有一张卡落到"前台已经结束"再被点，那一击是把卡片收掉
  并明说"这次审批已经结束了"。

## 球不自己摊开（`expandOnPending`，默认关）

提问或审批到了的时候，球**不会自己把面板弹开**。提醒由球自己的表现说：状态灯变色 + 徽标上的
数字。看见了、要作答的时候点一下球，面板就开了。打开这一格就是"一到就摊开"：那一支只在
`user-questions/request` / `approval/request` 到达时调一次 `overlay.expand()`，其余一切不变
—— 球照样变色、照样挂数字、照样能作答、网页端照旧同时弹卡片。

## 位置与拖动

- **两种形状都能拖**。收起的小球整块都能拖；展开后的面板，**任何不是控件的地方**都能拖
  （表头、统计行、条目之间的空隙、面板底部那行提示）。按钮与输入框自己会吃掉鼠标按下，
  所以拖不动它们 —— 这是刻意的，想在面板上点按钮时才不会误触。
- **初始位置在工作区右下角**（离右/下边缘各 24px）：右上角住着浏览器标签、文档页首与网页端
  自己的顶栏，而任务栏之上那一片通常是空的。
- 位置只记**一份**，记的是"收起的小球"落在哪（`window.json`）。所以展开、收起、拖动面板之后，
  球都回到那个角上 —— 既不是回到"面板左上角"，也不会每展开一次就往上爬一点。
- 拖出屏幕的那一下会被拉回虚拟桌面内：否则面板的头连同右上角那个收起按钮就永远点不到了。
  报到宿主那里的也是钳位之后的位置。
- 位置只在第一次运行时用默认值；之后你把它拖到哪，它就在哪（`window.json`），换 Profile 或
  删掉那个文件才会回到默认。

## 装与开

**从 GitHub 装（推荐）**：在 DSH Desktop 的内置终端里：

```
dsh plugin --profile desktop add github:y1s2y3/dsh-floating-ball
```

装完**重启 DSH Desktop**（插件名 `dsh-floating-ball`，Windows 专用）。

> 本机访问 codeload.github.com 慢/不通时，可以在 Profile 的 `package.json` 里把依赖写成镜像地址：
> `"dsh-floating-ball": "https://gh-proxy.com/https://codeload.github.com/y1s2y3/dsh-floating-ball/tar.gz/<commit>"`
> 再重启 Desktop。

**从本地目录装（开发时）**：Web UI 的 Plugins → Add plugin 里填本目录绝对路径，或命令行：

```
plugin_manager install_bundle target = <仓库绝对路径>
```

开启后立即生效，不需要重启 Harness（唯一例外见「自测与诊断」）。

- **运行目录**：`%LOCALAPPDATA%\dsh-session-ball\<profile 或 default>\`
  - `state-<n>.json`：宿主 → 球的状态（每次写一份新文件，球取序号最大的那份）
  - `act-<pid>-<seq>.json`：球 → 宿主的动作（一个动作一个文件，宿主消费后删除）
  - `<sha1-12>-ball.ps1`：当前这一代球脚本（内容哈希命名）
  - `window.json`：球的位置与展开状态（拖动/展开后记住）
  - `ball.log`：诊断日志（宿主与球都往里写）
  - `debug.flag`：放一个空文件进去，**下次球启动**时打开交互追踪
- **关掉**：把这一行的 `config.enabled` 设为 `false`，或者 `disabled: true`；两者都会杀掉球进程。

## 配置

写在 row 的 `config` 里（例如你自己的 Profile patch，或 Plugins 页面上的表单）：

| 键 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 总开关 |
| `ballSize` | `64` | 收起时的直径（像素） |
| `panelWidth` / `panelHeight` | `360` / `420` | 展开面板的宽度与**最大**高度。高度是上限：条目少时面板自己缩到内容那么高，多起来就长到这个数为止，再多就在面板里自己滚动。默认值是 420 而不是更小，因为面板现在是球的全部界面，而每条条目自己就带一个输入框 |
| `opacity` | `0.94` | 常态不透明度（球的样子只有这一个旋钮：形状、大小、可点性都不随模型在做什么而变；随状态变的只有颜色与光晕的呼吸） |
| `answerQuestions` | `true` | 允许在球上回答提问 |
| `answerApprovals` | `true` | 允许在球上批准/拒绝审批（有真实副作用） |
| `sound` | `true` | 出现提问/审批时响一声 |
| `expandOnPending` | `false` | 出现提问/审批时**自动**摊开面板。默认关：球的变色与徽标数字就是提醒，面板由你自己点开 |
| `promptMode` | `"auto"` | 条目里那个输入框怎么把话投进会话：`auto` = 模型在跑就插话(`steer`)、空闲就排队(`queue`)；也可以固定成 `queue` / `steer`。（默认 `lockComposeWhileBusy` 是开的，所以会话在输出时那个框本来也发不出去；想真的插话就把它关掉） |
| `lockComposeWhileBusy` | `true` | 那个会话**正在输出**期间禁用**它那条条目里**的输入框（见「在条目里给会话发话」） |
| `entryLimit` | `12` | 面板上最多同时留几条会话条目。超了先挤掉最旧的、此刻没事的那些；**正在输出、有卡片、或者带着还没确认的出错的一条都不挤**（最后那一条是"确认红"的入口）。被挤掉的与「×」收掉是同一件事，那个会话下一次有事照样回来 |

## 球不让开

球**在任何时刻都不改变自己的形状、大小与可点性**：模型操作鼠标键盘时，它照样停在原地、照样
可以点；大小、可点性与窗口的整体不透明度都不随模型在做什么而变（随状态变的只有状态色与光晕的
那口气：见「跑完了没有」）。代价是两条，都需要知情：

1. 球会出现在 `desktop_step` 返回的截图里（任何置顶窗口都躲不掉这一点）；
2. 模型如果点到球所在的那几像素上，那一下会落在球上而不是它想点的窗口上。

介意就把球收起来再开始桌面任务。

键盘的**常态**是安全的：窗口用 `WS_EX_NOACTIVATE` 创建，球不拿键盘焦点，模型敲的字进不了球。
唯一的例外是**你亲手点开的那个输入框**（条目里的框，或卡片里那个"自己写一句"的框）—— 那一段
时间里球是前台窗口，所以模型若正好在注入按键，那些字会落进这个框里（连回车也会被当成"发送"）。
球不检测这种冲突，也不为此让步。

## 它是怎么拿到数据的

只用 Host 既有事件，不新增会话事件、不改任何决策、不写会话日志：

| 事件 | 用途 |
|---|---|
| `agent/assistant-stream` | 这个会话在不在忙（步骤状态）、本轮输出 token 用量（球上只用于统计）、以及"回合号换了"这件事（它是条目回来的信号之一） |
| `session/event` | 提交后的权威信息：工具成败、回合状态（含出错）、以及**会话标题**（`session/title`）；顺带留下每个会话**第一条人写的消息**的一行摘要 |
| `api-session/added` / `status` / `activity` / `removed` | 会话目录：条目的出现与排序、在跑与否、最近活动时间 |
| `user-questions/request` | 提问（`prepend` 挂一层） |
| `approval/request` | 审批（同上） |

除此之外还**只读**地问了几个服务，都是 O(1) 或同步的：`ctx.sessionProjections.stateOf(session, 'title')`
（按 id 补一次标题投影）、`ctx.sessionTitle.get(session)`（投影空着时的兜底，每个会话最多每
30 秒问一次）、`ctx.sessions.get(id)`（把目录里的会话 id 换成 live Session）、
`ctx.workspaceRegistry.list()`（「＋ 新会话」要列出的工作区）。

这几个服务是**每次用到时现查的，不是挂载时查一次存起来**。原因很实在：Harness 的 Profile 是一棵
异步装配起来的树，插件挂载的那一瞬间它们常常还没就绪（实测 `ball.log` 第一行会写着"title 投影=没有 ·
live 会话表=没有 · sessionTitle 服务=没有"，而同一台机器上换个时机重启就都有）。挂载时查一次，
等于这次启动的球这辈子都用不到工作区注册表 —— 「＋ 新会话」按钮就会永远是灰的，而这跟用户到底
有没有工作区毫无关系。现查的代价只是一次表查找，好处是**服务晚一步就绪也照样能用上，不用重启
插件**；`ball.log` 里还会留一行"工作区注册表现在可见了：N 个（…）"。

它只往会话里写两样东西，都是**你亲手点出来的**：球上作答（提问 / 审批）与条目里发出去的那句话。
除此之外它不改任何决策、不写会话日志。

## 隐私与数据

① **不联网**：插件没有任何 HTTP / 遥测 / 上报代码，不向外发送任何数据。
② **不上传、不外发**：所有状态都在本机进程内；唯一的落盘是 `%LOCALAPPDATA%\dsh-session-ball\<profile>\`
里的临时 `state-*.json` / `window.json`（宿主自动只保留最近 60 份）与两份本地日志。
③ **日志不写你的话**：`ball.log` / `ball-v2.log` 只记录宿主/球的启动、审批 id、发送长度等元数据，
**不记录消息正文**、思维链、工具参数或结果。
④ **会话内容不进球**：球上只显示标题、状态、token 用量等元信息，不显示对话正文；面板里每条会话
只有一行由你自己决定是否查看的摘要。
⑤ 输入框聚焦的短暂时段球会成为前台窗口（为了让你打字），期间模型注入的按键可能落进这个框 ——
这是已知取舍，详见上文「键盘」。

## 自测与诊断

```powershell
npm run build && npm test      # 五个测试，都不碰你的桌面
```

- `test/approval-cards.mjs`：待办卡片（提问 / 审批）的生命周期回归（19 条）—— 网页端先答、
  球上先答、请求在别处被拒/被中止、凭据只收自己那张卡、提问卡片没被波及。改审批/提问的生命
  周期时先跑它。
- `test/panel-entries.mjs`：**会话条目的宿主半边**（66 条）—— 条目的出现与"闲下来仍留着"、卡片
  挂在**哪一条**上、「×」之后"我又在那个会话里说了句话 / 它开始新的一轮 / 目录说它开始跑了"都能
  让它回来、而**同一个回合里的步骤**不会（而且不会重复渲染）、出错与「知道了」的三种结局
  （红消失 / 条目留着 / 统计行干净）、**又出一次错会重新染红**、**「×」也顺手确认那条红**（收掉
  条目之后红不能还赖着 —— 那时已经没有按钮可点了）、**没确认的出错不会被面板上限挤掉**、认不出
  会话的卡片自己一条且也能被「×」收掉、以及**没有工作区时「＋ 新会话」照样能用**（兜底行 + 服务
  晚一步就绪也照样用上）。改条目的出现与消失规则、或改「＋ 新会话」时先跑它。
- `test/compose-lock.mjs`：**锁的宿主半边 + 整体状态口径**（35 条）—— `busy` 名单与每条条目

四个宿主侧的测试都把 `lib/` 挂到假 Host 上跑（`LOCALAPPDATA` 与 `PATH` 都指到测试目录，所以
没有 PowerShell、没有窗口），观察渠道是宿主每 120ms 落盘的状态文档。替身脚本那一份是**带 UTF-8
BOM** 写的：尾巴里有中文，而 Windows PowerShell 5.1 在没有 BOM 时按 ANSI 解码 `.ps1`（`ball.ps1`
本身是纯 ASCII 的，所以真文件不需要 BOM）。

诊断看 `ball.log`（宿主与球都往里写；开头的 `ball started` 那行写明 `debug=` 与脚本路径）；想看
交互追踪就在运行目录里放一个空的 `debug.flag`，**下次球启动**时生效。状态文档里带着版本号
（`state-<n>.json` 的 `v`，当前是 8）—— 排查"新版宿主配旧版球脚本"这类问题时先看它。

改代码之后要做什么：

- 改 `src/*.ts`：`npm run build` 之后要**重启 Harness**（`dsh web`）才会装载新的
  `lib/session-ball.js` —— 运行中的 Harness 会一直用启动时加载的那一份，宿主行的
  disable/enable 也不会让 Node 的 ESM 缓存失效。（dsh 自带的 HMR 只重载 Profile 配置，
  模块监听是 `root: []` 这种"没开"的状态，所以它也不会因为 `lib/` 变了而重新装载；想免重启
  就在自己的 Profile patch 里给 `hmr` 行加 `config.root` 指向插件目录。）
- 改 `resources/ball.ps1`：只要**重启球进程**（杀掉它，宿主 2 秒内会用新脚本重新拉起）即可。
  球脚本每次球启动都会从包里重新读一遍（内容哈希命名），所以不需要重启 Harness。

因为这两条差得挺远，**球脚本那一半是刻意不用等宿主重启的**：颜色口径进状态文档时升到 v7，而
球脚本对 v7 之前的文档会自己补上那个蓝色（见「跑完了没有」最后一节）。所以改完颜色以后先重启
球进程就能看效果，宿主那一半等你下次重启 Harness 时自然接上。

`src/session-ball.ts` 是插件入口（Config、事件订阅、作答挂载点、条目的组装与球上发言的目标解析）；
`src/mirror.ts` 是事件 → 视图状态的折叠层（纯数据，不碰窗口）；`src/overlay.ts` 管球进程的
生命周期与文件协议；`resources/ball.ps1` 是 WPF 窗口本身，**必须是纯 ASCII**（Windows
PowerShell 5.1 在没有 BOM 时按 ANSI 解码 `.ps1`），所以球上的每一句文案都是宿主机在 state JSON
里送进来的。

## 已知边界

- **置顶看门狗只对付"可见且不带置顶位"的窗口**：它每 1.5 秒从球自己的窗口沿 z 序往上走，撞到
  第一个这样的窗口才把球放回置顶带，并往 `ball.log` 写一行。所以**别的置顶窗口盖住球时它不动手**
  （那是别人的权利）。UAC 的安全桌面、锁屏、任务视图这类地方球进程根本看不到那些窗口，看门狗
  也就不会跟着乱动。
- **仅 Windows**：球是 Windows PowerShell + WPF 窗口；其它平台插件保持挂载但不启动任何东西。
- **条目不跨宿主重启保存**：球是观察窗，宿主重启后条目列表从零开始（哪个会话在跑、谁在等你，
  重新照着当下的情况长出来）；本地那条"还没发出去的新会话"条目也会随球进程重启消失。输入框里
  没发出去的半句话同样不跨重启保存。只有窗口位置/展开状态存在 `window.json`。
- **子代理只进统计**：球统计的是根会话在不在跑、有没有出错；子代理不计入"几个会话在跑"，也不
  出现在条目列表里，但会在统计行里报个数。
- **球上只显示状态，不显示内容**：要读完整输出请到网页端。球上的其他文字不能选中复制（用的是
  TextBlock）；输入框里的内容可以正常选中、复制、粘贴。
- **面板宽度与高度上限会被虚拟桌面尺寸限幅**，窗口位置每次都会夹回可见区域。
- **工作区列表是自绘的**（按钮 + Popup）：点「＋ 新会话」开合、点一行就选中并收起、点到别处由
  `StaysOpen=False` 收起。每行是两行小字（工作区名 + 目录），最多 300px 后自己滚动，列表比
  "一行一个标题"高一些。
- **新建会话落在哪儿取决于工作区注册表**：有工作区时它一定会登记进那个分组；注册表这一刻没有
  工作区（或者服务还没就绪）时走兜底行，新会话用 `cwd` 建在"最近在用的那个目录"里，因此**可能
  出现在侧边栏的「未分组」里**。想知道这一刻到底看见了几个工作区，看 `ball.log` 里那两行
  （挂载那一刻的可见性 + "工作区注册表现在可见了：N 个"）。
- **输入框的锁依赖"它在不在跑"这份判断**：判断来自会话目录与球自己看到的回合事件，两者错了锁
  就跟着错 —— 一个被误判成"还在跑"的会话会让那一条一直灰着。真遇上了先到网页端发消息，或者把
  `lockComposeWhileBusy` 关掉。**提问/审批卡片从不受它影响**。
- **红色要人来清，这是刻意的**：出错之后球一直红着，直到有人在那一条上按「知道了」、或者把那条
  「×」掉、或者那个会话自己又开始了一轮（见「出错的红要人来清」）。所以"一个被中止、之后你不再
  用的会话"不会再让球红很久 —— 代价是**你得去点一下**（或者就让它自己闲在那里，那也不影响别的
  会话）。这时"任务还在跑"仍然靠白晕看得见：还有会话在跑它就呼吸，全停下来就静了。
